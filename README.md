# 动画中割自动生成技术方案

## 一、项目概述

本项目针对动画制作中的**中割（Inbetweening）**环节进行自动化探索，旨在通过深度学习方法生成介于关键帧（Key Frames）之间的中间帧，以减轻传统手绘中割工作的负担。
---

## 二、方法设计与选型理由

### 2.1 技术选择：RIFE + RIFEm 模型

**选择 RIFE（Real-Time Intermediate Flow Estimation）的核心理由：**

| 设计考量 | 选择方案 | 替代方案 | 为什么不选 |
|---------|---------|---------|----------|
| **时间步灵活性** | RIFEm（任意时间步） | 固定中点插值 | 动画 1/3、2/3 等分割需要灵活的时间跳转；固定方案无法直接生成任意分割 |
| **速度与质量权衡** | RIFEm 中等规模 | 大型模型/小型模型 | 大模型计算量大，小模型细节丢失；中等规模在 1600px 下达到 ~4-5 FPS |
| **线稿特性处理** | 光流 + 上采样 + 对比度恢复 | 纯像素插值/其他生成模型 | 动画线稿包含高频细节且背景为白色；线性插值无法保持笔触清晰度；GAN-based方法易产生伪影 |
| **训练数据基础** | RIFE 在自然视频预训练 | 绝对动画线稿重训练 | 虽然预训练数据非动画，但大规模视频运动学习可迁移；重训练需要数百倍的动画线稿对集合 |

### 2.2 核心处理流程

```
输入关键帧 → 光流估计 → 特征融合 → 任意时间步插值 → 线稿规范化 → 输出中割
         ↑                                    ↑
    RIFE 编码器                        denoise + 对比度恢复
```

**关键技术点：**

1. **任意时间步推理** `timestep = offset / interval_count`
   - 优势：无需为不同分割比训练不同模型
   - 实现：利用 RIFEm 的时间条件化设计

2. **线稿规范化处理**（line_normalize）
   - 问题：RIFE 在白底线稿上产生模糊"雾霾"（attenuation of thin pencil lines）
   - 方案：`rgb = 1.0 - clip((1.0 - rgb) * 2.0, 0, 1)` 先恢复距离，再去除接近白色的压缩
   - 效果：保留原画的黑、蓝、红、绿线色

3. **时序翻转增强（Test-Time Augmentation, TTA）**
   - 仅对大位移帧（A0007、A0008）启用
   - 方法：前向和反向推理平均
   - 权衡：避免小位移帧上 TTA 引入的细微损伤

### 2.3 评测指标体系

按照动画中割行业标准定义评测集：

- **Chamfer 距离**：线集间的平均最近邻距离（像素）
  - 量化位置准确度；低值优先
  - 公式：$\text{Chamfer} = \frac{d_{\text{pred} \to \text{ref}} + d_{\text{ref} \to \text{pred}}}{2}$

- **容差 F1 评分**（Tolerance=3px）
  - 在 3px 容差内的真正例（TP）比例，综合精准率与召回率
  - 公式：$F_1 = \frac{2 \cdot \text{precision} \cdot \text{recall}}{\text{precision} + \text{recall}}$
  - 量化：笔画完整性和路径精确度

- **序列质心加速度**
  - 衡量帧间光学流畅度
  - 计算全序列中心轨迹的二阶导数范数

## 三、失败案例分析

### 3.1 KTK_04_246B 第二段（A0007~A0008）性能衰退

**现象：**
| 图像范围 | Chamfer Distance | F1@3px | 原因推断 |
|---------|------------------|---------|---------|
| 第一段 A0002-A0005 | 1.76±0.55 px | 0.805±0.010 | 小幅转动，外轮廓稳定 |
| **第二段 A0007-A0008** | **8.18±1.25 px** | **0.446±0.046** | **大幅转头，多重遮挡** |

**性能下降倍数**：Chamfer 增大 4.6 倍，F1 下降 44%

**深度原因分析：**

#### 3.1.1 大位移时的光流失败

- **问题**：当角色头部转动幅度接近 60°-90° 时，RIFE 的光流估计进入低置信区间
- **根本原因**：
  - 模型训练数据主要为自然视频（运动低于 10-20 像素）
  - 超大位移（>100px）的对应点搜索陷入局部最优
  - 新显露区域（遮挡消失）无前帧参考，只能通过内插合成

#### 3.1.2 遮挡与新区域生成

- **表现**：大转头后新显露的面部和细发区域笔画不连贯
- **技术成因**：
  - 前向光流在遮挡边界处梯度混乱
  - 网络被迫在没有参考的区域"幻想"线条，导致伪影
  - RIFE 的融合策略（基于置信度加权）无法精确处理新生成区域的笔触风格一致性

#### 3.1.3 细发梢递归破坏

- **现象**：细碎发梢在 4-5 帧递归插值后出现断裂或变淡（opacity 不稳定）
- **原因**：
  - 单根发丝宽度 1-2 像素，接近插值的奈奎斯特极限
  - 连续插值过程中，相邻帧的线条宽度微小波动累积
  - 线稿规范化时无法区别真实笔画与插值伪影

### 3.2 其他设计陷阱与规避

#### 3.2.1 尝试过但放弃的方案

| 尝试方案 | 预期 | 实际结果 | 放弃原因 |
|---------|------|---------|--------|
| **全序列 TTA** | 提升所有帧质量 | A0002-A0005 的细线反而模糊 | TTA 引入的过平滑对小位移有害 |
| **高分辨率推理（2× 上采样）** | 提升细节 | Chamfer ↑ 5.0, F1 ↓ 0.642 | 在上采样图上的光流线性化程度更差 |
| **多模型融合** | 多视角降低单点故障 | 融合权重计算复杂，实际无显著改善 | ROI/Token投入不符 |

#### 3.2.2 KTK_05_140 的多图层设计约束

**限制因素：**
- A 图层（源）与 B 图层（参考完成品）不对齐
- 独立处理各图层会导致帧间跳帧（jitter）
- 合成时色差导致的线条不连续

**现状**：仅生成初稿，但未进行合成评测（数据集类型不同，难以量化）

## 五、改进方向

### 5.1 方向一：动画线稿专用模型微调

**核心思想**：在 RIFE 预训练权重基础上，用动画中割数据集进行轻量级微调

**实现路径**：
1. **数据集构建**
   - 收集 500+ 个商业动画序列（宫崎骏、京都动画等）
   - 提取关键帧对与手绘中割真值
   - 标准化分辨率到 1600×1200（模型推荐输入）
   
2. **适配层设计**
   ```
   RIFE Encoder (冻结)
        ↓ 
   [Adapter: 1×1 Conv] ← 动画线稿特异特征
        ↓
   RIFEm Fusion (微调)
        ↓
   RIFE Decoder (冻结)
        ↓
   LineNorm (动画优化)
   ```
   - 仅微调融合层（~2% 参数）
   - 学习率: 1e-4, Batch: 8, Epoch: 20

3. **预期改进**
   - Chamfer: 4.15 → 3.0-3.5 px (-15~25%)
   - F1@3px: 0.679 → 0.72-0.75 (+5~8%)
   - 大位移帧（A0007/08）: F1 0.40 → 0.55-0.60
   - Token 投入: ~500K（数据处理 200K + 微调 300K）

**挑战与规避**：
- 过拟合：采用 LoRA 或部分参数冻结
- 数据少：使用 augmentation（旋转、缩放、不同线条风格替换）

---

### 5.2 方向二：多帧上下文与光流约束

**核心思想**：利用连续帧的时序一致性约束，改善大位移和遮挡处理

**实现方案**：
1. **光流后处理管道**
   ```
   光流输出 → 异常点检测 → 光流平滑 → 有效性掩码生成 → 融合
                ↑
          基于梯度幅和
   ```
   
2. **遮挡感知融合**
   - 在融合权重中显式加入遮挡掩码
   - 对遮挡消失的新区域使用边界外推而非幻想
   - 方法：基于光流的背景重映射（background warping）

3. **约束目标函数**（微调阶段新增项）
   ```
   Loss = L_perceptual + λ₁·L_flow_smooth + λ₂·L_occlusion
   ```
   - $L_{\text{flow\_smooth}}$：光流时间梯度最小化
   - $L_{\text{occlusion}}$：对新生成区域施加局部一致性
   - λ₁=0.1, λ₂=0.2（权重选择）

4. **预期改进** 
   - 大位移帧稳定性：±5px → ±2px（减少漂移）
   - 遮挡边界清晰度：主观评价 "模糊" → "可接受"
   - Token 投入: ~800K（新数据增强 300K + 约束优化 500K）

**技术优势**：
- 无需大规模重新标注（基于现有序列数据）
- 增量改进（微调 5-10 个 epoch）
- 可组合其他约束（如风格保留、线条宽度一致性）

---

### 5.3 其他探索方向（低优先级）

| 方向 | 复杂度 | 预期收益 | 理由 |
|------|--------|---------|------|
| 分层分割 + 独立生成 | 中 | +10% 细节 | 增加系统复杂度，需人工部件标注 |
| 矢量化后处理 | 中 | +5% 线条连贯 | 需要线条拓扑修复，算法复杂 |
| 集成手绘反馈环 | 高 | +20% 接受度 | 需要交互式 UI，超出纯推理范围 |
| 多尺度递归插帧 | 低 | -5% 性能 | 递归伪影累积，不推荐 |

### A.2 线稿规范化算法

```python
def line_normalize(frame):
    """恢复 RIFE 衰减的铅笔线，保留线色，去除白底雾霾"""
    rgb = frame[0].detach().float().cpu().permute(1, 2, 0).numpy()
    rgb = 1.0 - np.clip((1.0 - rgb) * 2.0, 0.0, 1.0)  # 恢复线条距离
    rgb[rgb.min(axis=2) > 0.985] = 1.0  # 去除接近白色的压缩
    return (np.clip(rgb, 0, 1) * 255).round().astype(np.uint8)
```

### A.3 F1@3px 计算

```python
def score(pred, ref, tolerance=3):
    d_ref = cv2.distanceTransform(1 - ref, cv2.DIST_L2, 3)
    d_pred = cv2.distanceTransform(1 - pred, cv2.DIST_L2, 3)
    forward = float(d_ref[pred > 0].mean())
    backward = float(d_pred[ref > 0].mean())
    tp_p, tp_r = (d_ref[pred > 0] <= tolerance).sum(), (d_pred[ref > 0] <= tolerance).sum()
    precision = tp_p / max(int(pred.sum()), 1)
    recall = tp_r / max(int(ref.sum()), 1)
    f1 = 2 * precision * recall / max(precision + recall, 1e-12)
    return {"chamfer_px": round((forward + backward) / 2, 3), "f1_tol3": round(f1, 4)}
```
